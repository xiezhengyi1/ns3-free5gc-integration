# GTP-U-Aware NR User-Plane Co-Simulation Design

Date: 2026-06-13

## 1. Objective

Modify the integration so that real free5GC/UERANSIM N3 user-plane packets are
controlled by packet-level ns-3 NR simulation rather than merely crossing a
fixed-delay CSMA segment.

The first version targets orchestrator-controlled bidirectional UDP flows. It
preserves the existing free5GC and UERANSIM control plane while making ns-3
virtual time authoritative during the user-plane experiment.

The design must provide:

- One-to-one mapping between a captured real GTP-U packet and an ns-3 shadow
  packet.
- Packet release or drop based on the shadow packet's NR outcome.
- Delay, jitter, loss, throughput, and queue metrics derived from packet
  events, not SLA targets or synthetic post-processing.
- Reproducible runs using explicit ns-3 seed and run numbers.
- Fail-closed behavior whenever the system cannot prove that a packet passed
  through the NR-controlled path.

## 2. Scope

### 2.1 Included

- Uplink and downlink UDP traffic generated by controlled agents.
- Existing UERANSIM gNB and free5GC UPF as the real GTP-U endpoints.
- Existing N3 TAP interception infrastructure.
- GTP-U parsing with TEID, optional QFI, inner UE IP, and inner UDP tuple.
- Per-flow NR bearer mapping, explicit RLC UM or AM selection, and packet-level
  PDCP/RLC/MAC/PHY behavior.
- Fixed UE and gNB positions with time-varying 3GPP UMi channel behavior.
- Per-tick and per-packet virtual-time telemetry.

### 2.2 Excluded From The First Version

- Arbitrary applications that emit traffic according to Linux wall-clock
  timers.
- General TCP support.
- Moving UEs.
- Replacing UERANSIM NAS, RRC, NGAP, or registration behavior.
- Making PFCP, NAS, or other control-plane timers follow ns-3 virtual time.
- Silent bypass when ns-3, the classifier, or the coordinator fails.

## 3. Time Model

The experiment has two phases.

### 3.1 Control-Plane Phase

free5GC and UERANSIM run normally using wall-clock time until:

- UE registration succeeds.
- PDU sessions are established.
- gNB-UPF GTP-U endpoints are ready.
- PFCP state is stable.

Control-plane components continue to use wall-clock time for heartbeats and
protocol timers throughout the run.

### 3.2 User-Plane Experiment Phase

ns-3 virtual time becomes the authoritative time source for controlled UDP
traffic. Wall-clock duration may be longer than simulated duration.

The orchestrator advances the experiment in virtual-time epochs:

1. The coordinator issues packet-send authorizations for the epoch.
2. UDP agents emit only the authorized packets.
3. The frame gate captures and classifies their real GTP-U frames.
4. ns-3 receives one shadow-packet injection for every captured packet.
5. ns-3 advances to the epoch boundary.
6. Shadow delivery and drop events resolve pending real frames.
7. The gate releases delivered frames and discards dropped frames.
8. The KPI collector closes the epoch and writes its output.
9. The next epoch starts only after all participants reach the barrier.

No user-plane metric uses wall-clock RTT or process scheduling latency.

## 4. Architecture

### 4.1 Controlled UDP Agents

One agent runs at each required traffic endpoint:

- UE-side agent inside the UE network namespace or container.
- Data-network-side agent reachable through the UPF.

An agent sends a packet only after receiving:

```text
SEND(flow_id, packet_id, direction, sequence, payload_size)
```

The payload includes an experiment header containing at least `packet_id`,
`flow_id`, `sequence`, and direction. This identifies the real packet without
depending solely on capture order.

Agents acknowledge successful local transmission to the coordinator. An
acknowledgement means only that the packet entered the Linux network stack; it
does not mean that the packet passed the NR model.

### 4.2 GTP-U Frame Gate

The frame gate owns the host-side TAP endpoints already connected to the gNB
and UPF N3 interfaces. It replaces transparent TAP-to-TAP forwarding.

Responsibilities:

- Read Ethernet frames from both ingress TAPs.
- Pass ARP and required non-experiment maintenance traffic according to an
  explicit allowlist.
- Capture experiment GTP-U frames without immediately forwarding them.
- Assign or recover `packet_id`.
- Store the original frame until the shadow packet resolves.
- Release the original frame exactly once on delivery.
- Discard it on a modeled drop or fatal mapping error.
- Enforce bounded pending-frame and byte limits.

The gate exposes a small framed IPC protocol over Unix domain sockets. The
protocol must use versioned binary headers and length-delimited payloads rather
than ad hoc text parsing.

### 4.3 Bearer Classifier

The classifier is a pure, independently testable module.

It parses:

- Ethernet and optional VLAN headers.
- IPv4 and UDP.
- GTP-U header and TEID.
- PDU Session Container and QFI when present.
- Inner IPv4 and UDP five-tuple.

Mapping precedence:

1. QFI and session context.
2. UE PDU IP plus inner five-tuple.

The session context is rendered from the scenario and updated from established
session state. A packet that cannot be mapped uniquely is not forwarded. The
experiment fails with a diagnostic containing the non-sensitive parsed header
fields.

### 4.4 Virtual-Time Coordinator

The coordinator is the only component allowed to advance epochs.

It maintains a packet state machine:

```text
AUTHORIZED -> CAPTURED -> INJECTED -> DELIVERED | DROPPED -> RELEASED | DISCARDED
```

Terminal invariants:

- A delivered packet must become released.
- A dropped packet must become discarded.
- A packet can be released at most once.
- No packet may be released before an ns-3 delivery event.
- At epoch close, every packet is terminal or explicitly pending with a future
  ns-3 expiry event.

The coordinator communicates with ns-3 through a versioned local IPC channel.
It sends injection commands and receives delivery, drop, queue, and epoch
completion events.

### 4.5 NR Shadow Transport

The current monolithic ns-3 program should be divided so the external packet
transport is isolated from topology construction and snapshot serialization.

For every captured real packet, ns-3 creates a shadow packet with:

- The same payload byte count used for radio resource consumption.
- The mapped UE, direction, flow, bearer, 5QI, and RLC mode.
- A packet tag carrying the external `packet_id`.
- A virtual enqueue timestamp.

The shadow packet follows the configured NR user-plane stack. Completion must
be observed at the destination-side packet sink or equivalent post-RLC/PDCP
delivery point. A successful completion emits `DELIVERED(packet_id, t_ns3)`.
Exhausted retries, queue overflow, explicit expiry, or modeled decoding failure
emit `DROPPED(packet_id, t_ns3, reason)`.

Flow configuration adds:

```yaml
rlc_mode: UM  # UM or AM; default UM
```

RLC mode is never inferred only from 5QI.

### 4.6 Window KPI Collector

The KPI collector consumes packet events rather than FlowMonitor cumulative
averages.

For each flow, direction, and tick it records:

- Packet counts: authorized, captured, injected, delivered, dropped, released.
- Bytes: injected, delivered, released.
- One-way delay samples.
- IP packet delay variation samples.
- Queue residence and queue occupancy samples.
- Drop reasons.
- Throughput based on delivered bytes in that virtual-time window.

It writes both raw packet-event JSONL and aggregated tick snapshots.

## 5. Packet Data Flow

### 5.1 Uplink

1. The coordinator authorizes a UE agent packet.
2. The UE agent sends the inner UDP packet.
3. UERANSIM encapsulates it into GTP-U.
4. The gate captures the gNB-side N3 frame.
5. The classifier maps it to a flow and bearer.
6. The original GTP-U frame is stored.
7. A same-size uplink shadow packet is injected into the mapped ns-3 UE bearer.
8. The NR stack schedules and transmits it.
9. On shadow delivery, the original frame is written to the UPF-side TAP.
10. free5GC UPF processes the unchanged original GTP-U frame.

### 5.2 Downlink

1. The coordinator authorizes a data-network agent packet.
2. The packet reaches the UPF and is encapsulated into GTP-U.
3. The gate captures the UPF-side N3 frame.
4. The classifier maps it to the destination UE and bearer.
5. The original frame is stored.
6. A same-size downlink shadow packet enters the corresponding ns-3 bearer.
7. On delivery, the original frame is written to the gNB-side TAP.
8. UERANSIM decapsulates and delivers the unchanged payload to the UE agent.

## 6. Delay, Jitter, Loss, And Queue Semantics

### 6.1 Delay

One-way radio delay is:

```text
shadow delivery virtual time - shadow enqueue virtual time
```

It covers modeled NR queueing, scheduling, transmission, HARQ, and RLC
behavior. It excludes Linux process delay, TAP handling wall time, and
free5GC/UERANSIM control-plane setup time.

### 6.2 Jitter

For consecutive successfully delivered packets of one flow and direction:

```text
IPDV_i = abs(delay_i - delay_(i-1))
```

Uplink and downlink are calculated separately.

### 6.3 Window Statistics

Each tick independently reports:

- Mean.
- P50.
- P95.
- P99.
- Maximum.
- Sample count.

An optional run-level summary may be produced separately. It must not replace
the current tick values.

### 6.4 Loss

Loss is generated only by modeled packet outcomes:

- PHY decoding failure.
- HARQ or RLC retry exhaustion.
- Actual modeled queue overflow.
- Configured virtual packet expiry.

Exceeding an SLA delay or jitter target marks a violation but does not itself
drop the packet.

### 6.5 Removed Synthetic Metrics

The implementation must remove or stop publishing as observed KPI:

- Deterministic sinusoidal metric factors.
- Queue bytes inferred only from requested-minus-allocated bandwidth.
- Dropped packets inferred from synthetic queue bytes.
- SLA target values presented as measured latency, jitter, or loss.

## 7. Radio And Randomness Model

The first version uses:

- Fixed UE and gNB positions.
- 3GPP UMi channel configuration.
- Shadow fading enabled.
- Time-varying small-scale fading with an explicit update period.
- Configurable PF or RR scheduler.
- Configurable TDD pattern applied to the actual NR configuration, not merely
  to a telemetry capacity estimate.
- Configurable numerology, bandwidth, frequency, transmit powers, and noise
  figures.

The scenario `seed` sets `RngSeedManager::SetSeed`. A new scenario field
`rng_run` sets `RngSeedManager::SetRun`. Stream assignment must be explicit for
channel, error, and traffic-related random variables.

Identical scenario, seed, and run values must reproduce the packet-event log.
Independent repetitions change `rng_run`, not arbitrary scenario values.

## 8. Backpressure And Resource Limits

The coordinator prevents wall-clock producers from outrunning virtual time:

- Agents cannot send without authorization.
- An epoch has configurable packet and byte budgets.
- The gate has hard pending-frame and byte limits.
- When limits are reached, the coordinator issues no further authorization.
- Pending frames are never evicted silently.

The first implementation should use a conservative default epoch duration and
allow it to be configured independently from the KPI tick. Multiple epochs may
compose one KPI tick.

## 9. Failure Semantics

The user-plane experiment is fail closed.

- Classifier ambiguity: discard the packet and fail the run.
- IPC disconnect: freeze new authorizations and fail the run.
- Epoch mismatch: fail the run and preserve diagnostics.
- Duplicate `packet_id`: reject and fail the run.
- ns-3 process exit: no bypass; fail the run.
- Gate queue overflow: stop authorization and fail if the barrier cannot
  recover.
- Shadow timeout: emit a modeled drop only when its configured ns-3 virtual
  expiry is reached.

Control-plane maintenance packets required to preserve established sessions
must be explicitly classified and bypassed outside the experiment KPI path.
No UDP experiment payload may use that bypass.

## 10. Configuration Changes

Add structured configuration rather than expanding unrelated positional CLI
arguments:

```yaml
ns3:
  rng_run: 1
  virtual_epoch_us: 1000
  channel_update_ms: 10
  shadowing_enabled: true

user_plane_gate:
  enabled: true
  max_pending_packets: 10000
  max_pending_bytes: 67108864
  allow_control_plane_bypass: true

flows:
  - flow_id: flow-telemed
    rlc_mode: UM
    virtual_expiry_ms: 100
```

Rendered run assets include:

- Bearer mapping table.
- Gate configuration.
- UDP agent flow plans.
- IPC socket paths and protocol versions.
- Seed, run, radio, and channel parameters.

## 11. Implementation Boundaries

The following boundaries should be introduced:

- `bridge/user_plane/gtpu.py`: pure protocol parsing and mapping types.
- `bridge/user_plane/coordinator.py`: packet state machine and epoch control.
- `bridge/user_plane/protocol.py`: versioned IPC messages.
- `bridge/user_plane/udp_agent.py`: controlled UDP endpoint.
- `bridge/user_plane/kpi.py`: packet-event window aggregation.
- `scripts/setup-user-plane-gate.sh`: TAP ownership and namespace setup.
- `sim/ns3/nr_shadow_transport.{h,cc}`: external packet injection and outcome
  events.
- `sim/ns3/nr_scenario_builder.{h,cc}`: topology and radio construction.

The exact frame gate implementation may be C++ or Rust for predictable packet
I/O. It must expose the same protocol and remain independently testable.

## 12. Verification Plan

### 12.1 Unit Tests

- Ethernet, IPv4, UDP, GTP-U, extension-header, QFI, and inner-tuple parsing.
- QFI-first and tuple-fallback mapping.
- Ambiguous and malformed packet rejection.
- Packet state-machine transitions and duplicate detection.
- KPI mean and percentile calculation from fixed event fixtures.
- Configuration validation for RLC mode, seed, run, and limits.

### 12.2 Component Tests

- Gate captures a frame and does not forward it before `DELIVERED`.
- `DELIVERED` releases the exact original bytes once.
- `DROPPED` never releases the frame.
- Coordinator closes an epoch only after all authorized packets resolve or
  remain validly pending.
- UDP agents emit exactly one packet per authorization.

### 12.3 ns-3 Tests

- Deterministic one-UE delivery and delay.
- UM and AM produce expected retransmission differences.
- Lower SINR increases retransmission, delay tail, or loss.
- Reduced bandwidth increases queueing and delay.
- UL-unfriendly TDD lowers uplink throughput and increases uplink delay.
- Identical seed/run reproduces events; a different run changes random
  outcomes.

### 12.4 End-To-End Acceptance

The implementation is accepted when:

1. Packet capture proves experiment GTP-U frames cannot travel directly between
   gNB and UPF.
2. Stopping ns-3 immediately reduces experiment throughput to zero.
3. For every checkpoint:

   ```text
   captured = delivered + dropped + pending
   released = delivered
   ```

4. No `packet_id` is released twice.
5. Hand-calculated delay and IPDV for a deterministic scenario match emitted
   events and tick statistics.
6. Radio parameter changes cause physically consistent throughput, delay-tail,
   and loss changes.
7. The same seed/run reproduces the raw packet-event stream.

## 13. Migration Strategy

Implement in narrow vertical slices:

1. Introduce packet IDs, IPC protocol, classifier, and a gate that remains
   closed.
2. Add a deterministic ns-3 shadow loopback transport and prove exact frame
   release.
3. Replace loopback with one-UE NR transport.
4. Add bidirectional and multi-flow bearer mapping.
5. Add channel variation, UM/AM, drop reasons, and complete KPI windows.
6. Remove legacy synthetic KPI generation after parity and acceptance tests
   pass.

The existing transparent CSMA harness remains available only as an explicitly
named legacy mode during migration. It must not be selected by the new
GTP-U-aware mode.
